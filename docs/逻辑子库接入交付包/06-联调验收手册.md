# 逻辑地址子库联调验收手册

## 1. 验收目标

验证从“定位服务拿到基站坐标”开始，到两个下游凭`scopeId`读取逻辑子库为止的完整链路。热词词面加工、ASR装载结果和地址机器人语义准确率不属于本次验收范围。

## 2. 验收前提

- 05号环境交接单已经填写；
- PostGIS迁移V1～V16已经执行；
- 全局地址库存版本已激活且有测试数据；
- `ADDRESS_SCOPE_ENABLED=true`；
- RabbitMQ vhost、exchange、routing key和两个独立队列已经创建；
- 两个下游只读账号已授权；
- 接入双方时钟已同步；
- 测试数据不含真实手机号、录音或敏感警情文本。

## 4. 功能验收用例

### AC-01 定位返回句柄

步骤：

1. 调用定位接口；
2. 检查成功响应的`data.addressScopeRef`。

通过标准：

- [ ] `scopeId`为合法UUID；
- [ ] `locationResolutionId`与定位结果一致；
- [ ] `locationResolutionVersion >= 1`；
- [ ] `inventoryVersion`等于环境激活版本；
- [ ] 新请求的`scopeStatus`为`READY`或`EMPTY`，不会返回`UNKNOWN`；
- [ ] 同一定位版本重复读取返回同一`scopeId`。

### AC-02 MQ句柄事件

步骤：分别从`location.address-scope.hotword.v1`和`location.address-scope.addressbot.v1`读取事件。

通过标准：

- [ ] 两个消费者都收到`address.scope.ready.v1`；
- [ ] 通过`address.scope.ready.v1.schema.json`校验；
- [ ] 外层`id`等于`data.eventId`；
- [ ] `subject`等于`data.addressScopeRef.scopeId`；
- [ ] `data.addressScopeRef.scopeStatus`与HTTP响应一致；
- [ ] 当前新事件包含`data.locationScope`；其经纬度、半径、定位方式分别与HTTP响应的`searchLongitude/searchLatitude/searchRadiusMeters/positioningMethod`一致；
- [ ] `coordinateSystem=WGS84`，直接圆形用例的`shapeType=CIRCLE`；
- [ ] 事件没有`items`、地址数组、数据库密码或定位几何；
- [ ] 两个消费者不是竞争消费关系。
- [ ] 两个消费者只能读取自己的队列，不能向exchange发布；

兼容性要求：2026-08-06之前产生的历史队列或Outbox消息可能没有`locationScope`，不得因此进入死信；地址机器人仍可通过`scopeId`查询，当前新消息则必须校验该字段。

### AC-03 数据库直查完整性

执行：

```sql
SELECT source_type, COUNT(*)
FROM dispatch_assist.logical_address_scope_item
WHERE scope_id = CAST(:scopeId AS uuid)
GROUP BY source_type
ORDER BY source_type;
```

通过标准：

- [ ] 查询成功且仅需`scopeId`；
- [ ] 只返回`BUILDING/AOI/POI/LOI`；
- [ ] 热词加载账号和地址机器人账号返回数量一致；
- [ ] 两个账号均不能写入视图或基础表；
- [ ] 两个账号均可只读查询`dispatch_assist`和`ai`业务schema；
- [ ] 结果数量与REST完整遍历数量一致。

### AC-03B 空逻辑子库

步骤：使用已知不在模拟地址数据覆盖区内的坐标创建句柄。

通过标准：

- [ ] HTTP响应和MQ事件均为`scopeStatus=EMPTY`；
- [ ] HTTP警告包含`EMPTY_ADDRESS_SCOPE`；
- [ ] `logical_address_scope_summary`能查询到该有效句柄及`EMPTY`状态；
- [ ] 下游不查询明细即可正常完成并ACK；
- [ ] `EMPTY`不被误报为数据库异常或消息发布失败。

### AC-04 不同电话范围隔离

步骤：使用两个不同基站坐标分别生成`scopeId-A`和`scopeId-B`。

通过标准：

- [ ] 两个句柄不同；
- [ ] 各自重复查询结果稳定；
- [ ] 查询A不会返回B的句柄字段；
- [ ] 下游没有缓存并复用上一通电话的`scopeId`。

### AC-05 REST游标完整遍历（备用路径选测）

仅当下游不能直连数据库并选择REST接入时执行。以`pageSize=100`持续调用`/{scopeId}/items`直到`hasMore=false`；数据库直连下游不需要执行此用例。

通过标准：

- [ ] 每页返回的`scopeId/inventoryVersion`一致；
- [ ] `nextCursor`能原样用于下一页；
- [ ] 所有页`inventoryId`重复数为0；
- [ ] 最终数量等于数据库直查数量；
- [ ] `hasMore=false`时遍历正常结束。

### AC-06 类型过滤

分别只读取`AOI`和`POI`。

通过标准：

- [ ] 结果不包含其他类型；
- [ ] 过滤后数量等于数据库`GROUP BY`结果；
- [ ] 小写输入能被正常归一化；
- [ ] 非法类型返回HTTP 400和`INVALID_REQUEST`。

### AC-07 重复事件幂等

步骤：向测试消费端重放同一个事件两次。

通过标准：

- [ ] 消费端幂等表只存在一条`eventId`；
- [ ] 不重复创建热词加载任务或地址处理任务；
- [ ] 第二次消费返回成功，不形成无限重试。

### AC-08 依赖故障恢复

在测试环境短暂阻断RabbitMQ或消费端数据库连接。

通过标准：

- [ ] 发布失败进入Outbox重试，不丢失定位结果；
- [ ] 恢复后事件最终发布；
- [ ] 消费端数据库恢复后能继续处理；
- [ ] 失败日志包含`eventId/scopeId`但不包含凭据和敏感对话；
- [ ] 重试没有产生不同事件ID。

### AC-09 句柄过期

在测试环境使用较短TTL创建句柄并等待过期。

通过标准：

- [ ] 过期后逻辑视图不再返回数据；
- [ ] REST返回HTTP 400和`INVALID_REQUEST`；
- [ ] 消费端停止使用该句柄并产生可观测告警；
- [ ] 不把旧`scopeId`重新绑定到新范围或新库存版本。

### AC-10 安全边界

通过标准：

- [ ] 只读账号只能查询完整业务schema，不能写入或执行数据库管理操作；
- [ ] REST生产入口启用TLS和服务身份认证；
- [ ] MQ、日志和验收截图不含数据库密码或Token；
- [ ] 不记录手机号、录音和完整报警对话；
- [ ] 不向下游推送完整地址数组。

## 5. 性能验收

性能计时起点至少为定位服务收到基站WGS84坐标，终点为逻辑子库句柄返回并可执行首次业务条件查询。`scopeStatus`只允许使用短路`EXISTS`生成，不得在主链路执行完整`COUNT(*)`。另行记录：

| 坐标到`scopeId` P99 | 【项目填写】 |  |  |
| `scopeId + 业务条件`首次查询P95 | 【项目填写】 |  |  |

| 错误率 | 【项目填写】 |  |  |
| Outbox最大可接受延迟 | 必须小于TTL，项目填写 |  |  |
| 数据库连接池峰值 | 【项目填写】 |  |  |

历史开发机参考证据：100万地址、示例句柄2,904条、坐标到句柄约294.69 ms、数据库前101条执行约4.793 ms。2026-08-05在167完成链路验收：重启后API 79.591 ms，预热后API 9.765 ms、Broker confirm 279.737 ms、双队列消息可直接读取409 ms、完整验证658 ms；同一句柄范围命中35,985条。V16整改后进一步验证：`READY/EMPTY`状态在HTTP、数据库和MQ中一致；创建句柄的短路`EXISTS`分别为0.333/0.340 ms且使用GiST；35,985条范围内按类型和名称筛选前100条执行46.883 ms。

2026-08-06当前版本补充验证：54项自动化测试通过；API坐标到`scopeId`为11.249 ms；新消息的`locationScope`与HTTP最终搜索中心、半径和定位方式一致；热词在线消费者发生真实投递，地址机器人队列中的完整CloudEvent通过读取校验；两个下游只读账号查询同一逻辑子库均为35,985条；Outbox为`PUBLISHED`且重试0次。完整验收脚本用时1,467 ms，包含MQ轮询、消息契约核验、双账号完整计数和分类统计，不可当作定位接口或单次业务SQL时延。以上结果证明功能链路和单次查询可用，不替代目标并发下的P95/P99压测。
