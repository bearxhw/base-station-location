## 1. 交付目标

本目录是面向接入方的最小完整资料，不要求接入方通读定位算法、邻区融合或百万数据模拟文档。

接入方只需要理解：定位服务为每通电话生成一个`scopeId`。该ID绑定本次定位范围和固定地址库存版本，但不会复制一份物理地址库。定位服务通过消息队列通知句柄已就绪，下游再凭`scopeId`读取范围内的AOI、POI、LOI和建筑记录。

消息中的`scopeStatus`用于区分：`READY`表示范围内至少有一条候选地址；`EMPTY`表示句柄创建成功但范围内没有地址；旧消息未携带该字段时按`UNKNOWN`处理。状态判断只查找到第一条空间命中即停止，不计算地址总数。当前生产者还会发送与该句柄同版本的`locationScope`（WGS84中心、半径和定位方式），供地址机器人做距离计算；热词服务可忽略该字段。

当前推荐的读取方式为：

1. 内部可信服务：默认使用独立只读账号访问完整PostGIS业务库，并按`scopeId`查询逻辑视图；
2. 不允许共享数据库的服务：使用REST游标分页接口；
3. 消息队列只传句柄和小体量定位范围元数据，不传完整地址数组和数据库凭据。

## 4. 交付边界

本交付包提供稳定的句柄和地址读取能力，不负责：

- 把地址名称加工成ASR词面；
- 热词去重、Top-K、权重和厂商载荷生成；
- 地址机器人的语义提取和父子层级推理；
- 运营商或CTI获得基站坐标的外部耗时；
- 未经目标环境压测确认的生产SLA。

## 5. 上线前必须补齐

静态文档不能携带密码和密钥。交付负责人必须填写05号环境交接单，并通过配置中心或密钥系统交付凭据。只有在06号验收手册全部通过后，才可视为接入完成。
