# `address.scope.ready.v1` RabbitMQ事件契约

## 1. 事件用途

该事件表示某次报警电话的逻辑地址子库句柄已经可读。定位服务是生产者；热词加载服务和地址机器人是两个独立消费者。消息携带句柄以及生成该句柄时使用的最终标准化定位范围，不发送完整地址数据。事件名称中的`ready`表示句柄准备完成，不保证范围内一定存在地址；是否有候选由`scopeStatus`说明。

## 2. 当前RabbitMQ拓扑

| 项目 | 契约值 |
|---|---|
| 协议 | AMQP 0-9-1 |
| Vhost | `/location` |
| Exchange | `location.address-scope.v1`，durable direct |
| Routing key | `address.scope.ready.v1` |
| 热词队列 | `location.address-scope.hotword.v1` |
| 地址机器人队列 | `location.address-scope.addressbot.v1` |
| 死信Exchange | `location.address-scope.dlx.v1` |
| 死信队列 | 主队列名称加`.dlq` |
| 消息持久性 | delivery mode 2 |
| CloudEvents版本 | `1.0` |

两个消费者使用不同队列和不同账号，因此每个消费者都能收到同一事件，不会互相竞争消息。队列和绑定由定位组件部署脚本创建，下游只订阅自己的队列。

## 4. 关键字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | UUID string | 是 | 事件幂等键；RabbitMQ `message_id`相同 |
| `specversion` | string | 是 | 固定`1.0` |
| `source` | string | 是 | 默认`ids-location-address-scope` |
| `type` | string | 是 | 固定`address.scope.ready.v1` |
| `time` | date-time | 是 | Outbox事件产生时间 |
| `subject` | UUID string | 是 | 等于`scopeId` |
| `datacontenttype` | string | 是 | 固定`application/json` |
| `data.eventId` | UUID string | 是 | 与外层`id`一致 |
| `data.requestId` | string | 是 | 定位请求追踪ID |
| `data.sessionId` | string | 是 | 报警会话ID |
| `data.alarmId` | string/null | 否 | 已产生警情时携带 |
| `data.addressScopeRef.scopeId` | UUID string | 是 | 查询逻辑子库的唯一句柄 |
| `data.addressScopeRef.locationResolutionId` | UUID string | 是 | 定位结果ID |
| `data.addressScopeRef.locationResolutionVersion` | integer | 是 | 句柄绑定的定位版本 |
| `data.addressScopeRef.inventoryVersion` | string | 是 | 句柄绑定的地址库存版本 |
| `data.addressScopeRef.scopeStatus` | string | 新消息是 | `READY`表示至少一条候选；`EMPTY`表示有效空范围；旧消息缺失时按`UNKNOWN`处理 |
| `data.locationScope.centerLongitude` | number | 当前新消息是 | 最终`searchArea`参考中心的WGS84经度 |
| `data.locationScope.centerLatitude` | number | 当前新消息是 | 最终`searchArea`参考中心的WGS84纬度 |
| `data.locationScope.radiusMeters` | number | 当前新消息是 | 最终搜索范围的参考/包络半径，单位米 |
| `data.locationScope.coordinateSystem` | string | 当前新消息是 | 固定`WGS84` |
| `data.locationScope.shapeType` | string | 当前新消息是 | `CIRCLE`或`MULTI_CIRCLE_UNION` |
| `data.locationScope.positioningMethod` | string | 当前新消息是 | 本次定位方式，例如`BASE_STATION_RADIUS_CIRCLE` |
| `data.locationScope.evidenceLevel` | string | 当前新消息是 | 本次定位证据等级 |

`locationScope`由已保存的最终定位结果生成，与`addressScopeRef.locationResolutionId/version`严格对应。直接圆形模式下，它与CTI/运营商上游输入经WGS84标准化后的中心和半径一致；邻区融合时发送最终搜索范围的参考圆，精确空间边界仍以`scopeId`为准。2026-08-06之前产生的历史消息可能没有该字段，消费者必须继续允许其通过Schema校验。

## 5. 生产与投递语义

- 定位结果、逻辑子库句柄、`locationScope`和Outbox在同一PostGIS事务中提交；
- RabbitMQ不可用时定位结果仍保留，Outbox按配置延迟重试；
- 发布使用publisher confirm和mandatory标记；
- `eventId`由`eventType + scopeId`确定性生成，重试时不变；
- 当前为至少一次投递，消费者必须按`id`幂等；
- 消息不得新增完整地址数组、数据库凭据、手机号、录音或报警对话。

## 6. 消费规则

1. 使用分配给本服务的MQ账号连接`/location`；
2. 只消费本服务队列，不重新声明或修改exchange；
3. 校验`type/schemaVersion`并用配套JSON Schema校验消息；
4. 按`id`执行幂等检查；
5. 地址机器人读取`locationScope`作为中心、半径和距离排序上下文，但不得用它自行改变范围或重建另一套子库；热词服务可以忽略该字段；
6. `scopeStatus=READY`时，用`scopeId`和本服务只读数据库账号按需查询；`EMPTY`时记录空结果并结束本次处理；`UNKNOWN`时允许查询确认；
7. 完成本服务处理后手动ACK；
8. 临时故障NACK并有限重试，无法处理时进入本服务`.dlq`。

## 7. 权限边界

- `location_publisher`只能配置和发布`location.address-scope.*`资源；
- `location_hotword`只能读取热词主队列及其DLQ；
- `location_addressbot`只能读取地址机器人主队列及其DLQ；
- 管理账号不交付业务下游；
- 下游不能消费对方队列，也不能向exchange发布消息。

## 8. 版本兼容

V1消费者必须忽略未知可选字段。`locationScope`是向后兼容的新增字段：当前生产者始终发送，但机器Schema为兼容历史Outbox和队列消息仍允许缺失。删除字段、修改字段类型/语义或新增必填字段时必须发布新事件类型。机器契约见[address.scope.ready.v1.schema.json](address.scope.ready.v1.schema.json)。
